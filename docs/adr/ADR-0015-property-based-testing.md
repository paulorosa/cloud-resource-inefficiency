# ADR-0015: Property-Based Testing for Edge Cases

## Status
Accepted

## Context

Testes tradicionais (unit tests) verificam exemplos específicos:
```python\n# Teste tradicional\ndef test_calculate_savings():\n    volume = CloudResource(..., size_gb=100, type='gp2')\n    pricing = PricingDetails(hourly_rate=0.10)\n    savings = calculate_monthly_savings(volume, pricing)\n    assert savings == 72.0  # 100GB * $0.10 * 730 hours\n```\n\nProblemas:\n- Cobre apenas casos específicos\n- Edge cases podem ser missed (ex: 0 GB, -1 GB, 1 million GB)\n- Não teste combinações\n\nProperty-Based Testing (PBT):\n```python\n# PBT com Hypothesis\n@given(\n    size_gb=st.integers(min_value=0, max_value=1_000_000),\n    hourly_rate=st.floats(min_value=0, max_value=1_000),\n)\ndef test_calculate_savings_property(size_gb, hourly_rate):\n    \"\"\"Propriedade: Savings sempre não-negativo\"\"\"\n    volume = CloudResource(..., size_gb=size_gb)\n    pricing = PricingDetails(hourly_rate=hourly_rate)\n    savings = calculate_monthly_savings(volume, pricing)\n    \n    assert savings >= 0  # Propriedade universal\n    assert isinstance(savings, float)  # Type property\n```\n\nHypothesis gera 100+ exemplos aleatorios:\n```\nTestedative 1: size_gb=0, hourly_rate=0 → savings=0 ✓\nTestedative 2: size_gb=500, hourly_rate=0.05 → savings=18,250 ✓\nTestedative 3: size_gb=999999, hourly_rate=999 → savings=???\n... 97 more...\n```\n\n## Decision\n\nImplementar **Property-Based Testing com Hypothesis**:\n\n### Instalação\n```toml\n# pyproject.toml\n[project.optional-dependencies]\ndev = [\n    \"pytest>=7.0.0\",\n    \"pytest-cov>=4.0.0\",\n    \"hypothesis>=6.80.0\",  # PBT framework\n    \"mypy>=1.0.0\",\n    \"flake8>=6.0.0\",\n    \"pyyaml>=6.0\",\n]\n```\n\n### Exemplo 1: Formatação de Output\n```python\n# tests/test_formatters.py\nfrom hypothesis import given, strategies as st\nfrom cloud_resource_inefficiency.core.models import ScanResult, Opportunity\nfrom cloud_resource_inefficiency.formatters.output import ScanResultFormatter\n\n@given(\n    num_opportunities=st.integers(min_value=0, max_value=1000),\n    monthly_savings=st.floats(min_value=0, max_value=10_000),\n)\ndef test_text_formatter_is_valid(\n    num_opportunities: int,\n    monthly_savings: float,\n) -> None:\n    \"\"\"Propriedade: Text formatter sempre retorna string válida\"\"\"\n    # Generate synthetic opportunities\n    opportunities = [\n        Opportunity(..., estimated_monthly_savings=monthly_savings * (i+1))\n        for i in range(num_opportunities)\n    ]\n    result = ScanResult(opportunities=opportunities)\n    \n    # Formatação deve sempre funcionar\n    text_output = ScanResultFormatter.to_text_summary(result)\n    \n    # Propriedades universais\n    assert isinstance(text_output, str)\n    assert len(text_output) > 0\n    assert \"CLOUD FINANCIAL INEFFICIENCY\" in text_output\n    assert f\"Total Opportunities: {num_opportunities}\" in text_output or num_opportunities == 0\n\n@given(st.text())\ndef test_markdown_sanitization_prevents_injection(text: str) -> None:\n    \"\"\"Propriedade: Markdown sanitization previne quebra de tabela\"\"\"\n    # Qualquer texto, quando sanitizado, não deve quebrar layout Markdown\n    sanitized = ScanResultFormatter._sanitize_markdown(text)\n    \n    # Não deve conter pipes não-escapados (que quebram tabelas)\n    # Nota: depois de escape, pipes são \\\\|\n    # Mas se houver literal |, é porque foi escaped\n    assert not (\"\\n\" in sanitized and \"|\" in sanitized)  # Sem newlines em cells\n```\n\n### Exemplo 2: Pricing Calculation\n```python\n# tests/test_pricing.py\nfrom hypothesis import given, strategies as st, assume\n\n@given(\n    hourly_rate=st.floats(min_value=0, max_value=1000, allow_nan=False, allow_infinity=False),\n    months=st.integers(min_value=1, max_value=120),  # 1-10 anos\n)\ndef test_pricing_calculation_properties(\n    hourly_rate: float,\n    months: int,\n) -> None:\n    \"\"\"Propriedades universais de cálculo de preço\"\"\"\n    # Evitar casos inválidos\n    assume(hourly_rate >= 0)\n    assume(months >= 1)\n    \n    pricing = PricingDetails(\n        hourly_rate=hourly_rate,\n        provisioned_iops=100,\n    )\n    \n    # Calcular custo\n    monthly_cost = pricing.calculate_monthly_cost(hours_per_month=730)\n    annual_cost = monthly_cost * 12\n    \n    # Propriedades:\n    # 1. Custo sempre não-negativo\n    assert monthly_cost >= 0\n    assert annual_cost >= 0\n    \n    # 2. Custo anual >= custo mensal\n    assert annual_cost >= monthly_cost\n    \n    # 3. Custo mono-tônico (aumentar rate aumenta cost)\n    pricing2 = PricingDetails(\n        hourly_rate=hourly_rate * 1.1,  # 10% mais caro\n        provisioned_iops=100,\n    )\n    monthly_cost2 = pricing2.calculate_monthly_cost(hours_per_month=730)\n    assert monthly_cost2 >= monthly_cost * 0.99  # Allow rounding error\n```\n\n### Exemplo 3: Resource Collection\n```python\n# tests/test_collectors.py\nfrom hypothesis import given, strategies as st\n\n@given(st.text(alphabet=st.characters(blacklist_characters='\\x00'), max_size=64))\ndef test_collector_handles_arbitrary_region(region_str: str) -> None:\n    \"\"\"Propriedade: Collector não crasheia com região arbitrária\"\"\"\n    assume(len(region_str) > 0)  # Pelo menos 1 char\n    \n    # Usar mock collector\n    collector = MockResourceCollector()\n    \n    try:\n        resources = collector.collect(region=region_str)\n        # Sempre retorna lista (mesmo se vazia)\n        assert isinstance(resources, list)\n        assert all(isinstance(r, CloudResource) for r in resources)\n    except ValueError as e:\n        # Apenas ValueError é aceitável para input inválido\n        # Outras exceções são bugs\n        assert \"invalid\" in str(e).lower() or \"unsupported\" in str(e).lower()\n```\n\n### Configuração pytest\n```ini\n# pyproject.toml ou pytest.ini\n[tool.pytest.ini_options]\nminversion = \"7.0\"\ntestpaths = [\"tests\"]\npythonpath = [\"src\"]\n\n[tool.hypothesis]\nprofile = \"default\"\n# Aumentar iterations para CI/CD\n# Reduzir para development (mais rápido)\n```\n\n## Rationale\n\n1. **Cobertura Universal**: Testa muitos exemplos ao invés de poucos\n2. **Bug Discovery**: Encontra edge cases que developer não pensou\n3. **Regression Prevention**: Shrinking mostra exemplo mínimo que falha\n4. **Time Investment**: Escreveir uma property test cobre 100+ casos\n5. **Complement Unit Tests**: PBT não substitui, mas complementa\n\n## Consequences\n\n### Positive\n- ✅ Encontra bugs em edge cases\n- ✅ Testes mais concisos (property vs muitos exemplos)\n- ✅ Regressões detectadas rapidamente\n- ✅ Documentação viva (propriedades explicam comportamento esperado)\n- ✅ Confiança aumentada\n\n### Negative\n- ❌ Learning curve (nova forma de pensar em testes)\n- ❌ CI/CD mais lento (100+ iterações por property)\n- ❌ Flaky tests possíveis (randomness pode ser instável)\n- ❌ Debugging difícil (\"por que esse valor aleatório falhou?\")\n- ❌ Nem sempre aplicável (sistemas determinísticos sim, APIs não)\n\n## Alternatives Considered\n\n### 1. Fuzzing\n```python\n# AFL, libFuzzer para Python\n# Gera entrada aleatória e tenta encontrar crashes\n```\n**Rejeitado**: Mais agressivo que PBT. Bom para encontrar security issues, não funcionalidade.\n\n### 2. Parameterized Tests Manualmente\n```python\n@pytest.mark.parametrize(\n    \"size,rate,expected\",\n    [(0, 0, 0), (100, 0.10, 72), (1_000_000, 999, ...)]\n)\ndef test_pricing(size, rate, expected):\n    assert calculate(size, rate) == expected\n```\n**Adotado Parcialmente**: Bom para exemplos conhecidos, mas não substitui PBT.\n\n### 3. QuickCheck (Haskell Style)\n```python\n# fast-check library (JS), QuickCheck (Haskell)\n# Similar a Hypothesis, mas menos Python-idiomatic\n```\n**Rejeitado**: Hypothesis é mais Pythônico.\n\n## Related Decisions\n\n- **ADR-0010**: Type hints facilitam PBT (st.just() + strategies)\n- **ADR-0014**: CI/CD executa PBT em matriz Python versions\n\n## Implementation References\n\n### Key Files\n- `tests/test_formatters.py` - PBT para ScanResultFormatter\n- `tests/test_pricing.py` - PBT para pricing calculations\n- `tests/test_collectors.py` - PBT para resource collectors\n- `tests/conftest.py` - Hypothesis fixtures\n\n### Hypothesis Strategies (Generators)\n```python\nfrom hypothesis import strategies as st\n\n# Basic types\nst.integers(min_value=0, max_value=100)\nst.floats(min_value=0, max_value=1000, allow_nan=False)\nst.text(alphabet=st.characters(), max_size=100)\nst.booleans()\nst.none()\n\n# Composites\nst.lists(st.integers(), min_size=0, max_size=100)\nst.dictionaries(st.text(), st.integers())\nst.tuples(st.text(), st.integers())\nst.one_of(st.integers(), st.floats())\n\n# Custom\n@st.composite\ndef cloud_resources(draw):\n    return CloudResource(\n        resource_id=draw(st.text()),\n        region=draw(st.sampled_from([\"us-east-1\", \"eu-west-1\"])),\n        tags=draw(st.dictionaries(st.text(), st.text())),\n    )\n\n@given(cloud_resources())\ndef test_with_custom(resource):\n    pass\n```\n\n### Running PBT\n```bash\n# Rodas todos os testes (unit + property)\npytest -v\n\n# Apenas property tests\npytest -v -k \"property\"\n\n# Com verbosidade (mostra exemplos gerados)\npytest -v -s\n\n# Seed específico (replay failure)\npytest -v --hypothesis-seed=123456789\n\n# Aumentar iterations (para CI/CD)\nPYTHONHASHSEED=0 pytest -v\n```\n\n### Hypothesis Profiles\n```python\n# conftest.py\nfrom hypothesis import settings, HealthCheck\n\n# Development: Rápido, menos iterações\nsettings.register_profile(\"dev\", max_examples=100)\n\n# CI/CD: Agressivo, muitas iterações\nsettings.register_profile(\"ci\", max_examples=1000)\n\n# Load profile\nif os.getenv(\"CI\"):\n    settings.load_profile(\"ci\")\nelse:\n    settings.load_profile(\"dev\")\n```\n\n## Notes\n\n- **Shrinking**: Se teste falha, Hypothesis automaticamente encontra exemplo mínimo (shrinking)\n- **Seeds**: Resultado de teste pode ser reproduzido com seed (`--hypothesis-seed`)\n- **Flakiness**: Se teste intermitentemente falha, verificar randomness bugs\n- **Performance**: PBT é lento. Considerar `@settings(deadline=None)` para operações I/O\n- **Stateful Testing**: Hypothesis também suporta stateful testing (mocking state machines)\n"
